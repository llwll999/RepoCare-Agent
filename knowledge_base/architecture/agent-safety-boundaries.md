# RepoCare 三 Agent 与 RAG 边界

## RAG 的职责

RAG 只从本地脱敏文档中检索与 Bug 相关的规则、接口说明和排查步骤。每个检索片段必须保留文件路径和标题，供调试 Agent 引用。RAG 不执行命令、不生成写入权限，也不代表测试结论。

## 三 Agent 的职责

- 调试 Agent：读取源码、测试与 RAG 证据，输出根因假设和引用。
- 修改 Agent：只生成受控 diff，不能直接改真实代码。
- 测试 Agent：在独立 Sandbox 复现 Bug，并验证补丁是否通过回归测试。

## 不可绕过的门禁

即使 RAG 或模型给出高置信度建议，也必须经过状态机、人工批准、Sandbox 测试和第二次真实写入确认。知识库命中不等于修复正确。
